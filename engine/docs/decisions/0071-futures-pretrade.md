# 0071 — Futures pre-trade checks

Status: accepted for futures risk checks before a paper order is simulated. A failed check vetoes the order with a reason code. Live orders stay locked.

## Context

TASK 15.A.02 asks to check max leverage, notional, margin buffer, mark/index freshness, funding state, liquidation distance, stop policy, and kill switch before paper order simulation. Boundary and stale-feed fixtures must veto unsafe orders. Every veto has a reason code.

Design page 2 says a risk denial returns a stable reason code and writes an audit event. A stale price blocks a new automatic entry and preserves reduce-only separately. Design page 8 says a kill switch blocks new risk-increasing orders and that a policy-defined risk-reducing exit remains possible. It also names the leverage ceiling, maintenance margin, and mark/index freshness. Design page 9 names the admin caps and names no numbers. Decision 0055 compares the caller caps and does not submit an order. Decision 0056 reports stale mark/index, stale funding, and a funding gap. Decision 0070 simulates a futures paper order and does not apply these checks.

## Decision

`services/futures-pretrade.mjs` exports `createFuturesPreTradeStore`, `checkFuturesPreTrade`, `readFuturesPreTrade`, `FUTURES_PRETRADE_REASON_CODES`, and `FUTURES_PRETRADE_LIMITATIONS`.

`checkFuturesPreTrade` calls `readFuturesRisk` for max leverage, notional, the maintenance-margin buffer, and liquidation distance. Equal to a max or a floor passes. Above a max or below a floor returns action `NO_TRADE` and does not simulate. The reason codes are `max leverage`, `notional`, `margin buffer`, and `liquidation distance`. The liquidation distance stays the caller decimal. Its formula stays `NOT IN SOURCE`.

Mark/index freshness and funding state come from `evaluateFuturesFaults`. A stale mark or index on a new entry uses reason code `mark/index freshness` and error `stale mark/index`. The same stale mark does not veto a reduce-only exit. A funding gap or stale funding uses reason code `funding state` and vetoes the order, including a reduce-only order. An age equal to the caller lag threshold is not stale. Open-interest discontinuity and a liquidation-feed outage are not pre-trade vetoes in this module.

A stop policy must say `configured` true. `configured` false is reason code `stop policy`. The source names no stop price. A kill switch that is on blocks a risk-increasing order with reason code `kill switch` and does not cancel, fill, or reconcile. A reduce-only order is not blocked by the kill switch. Turning the switch off does not replay a vetoed decision. The same idempotency key and body return the stored audit and do not apply the quantity twice.

A passing check then calls `appendFuturesPaperOrder`. A Spot order is `product is not supported` and is not stored. A veto writes one audit. `venueClient` stays null. `liveOrderSubmitted` stays false. `liveTrading` stays `OFF`. `liveOrdersLocked` stays true. No PostgreSQL table was added. `futures-risk.mjs`, `futures-faults.mjs`, and `futures-paper.mjs` were not changed.

## Evidence

`pnpm test:futures-pretrade` passed 3/3, duration_ms 249.450762. Leverage `2` against max `2`, notional `10` against max `10`, buffer `0.050` against floor `0.05`, and distance `0.2` against floor `0.2` simulate one long of quantity `2` at `100`. Replaying that key leaves one order. Leverage `2.1` is reason code `max leverage` and error `leverage cap is exceeded`. Notional `10.1` is `notional`. Buffer `0.049` is `margin buffer`. Distance `0.199` is `liquidation distance`. None of those four checks appends an order. A mark age equal to lag `1000` is accepted. A mark older than that lag is `mark/index freshness` with error `stale mark/index` and feed reason `late event`, and the long stays quantity `2`. A funding sequence `10` after watermark `8` is `funding state` with error `funding gap`. Stale funding is the same reason code with error `stale funding`. A reduce-only close of quantity `1` at `110` while the mark is stale and the kill switch is on returns PnL `10` and leaves quantity `1`. The same reduce-only close is vetoed when funding has a gap. A new entry while the kill switch is on is `kill switch` and leaves quantity `1`. Stop policy `configured` false is `stop policy` and appends nothing. A later reduce-only close of the remaining quantity returns PnL `10` and realized PnL `20`. Replaying the kill key does not add an order. A Spot object `fixture-spot-order` is `product is not supported` and is not stored. `bearer fixture-token` is `secret value is not allowed` and is not echoed. Price `100.2` is `price is not on the tick` and is not echoed. An open-interest discontinuity and a liquidation-feed outage still simulate. A Customer is `role scope denied` and writes no audit. The module calls `readFuturesRisk`, `evaluateFuturesFaults`, and `appendFuturesPaperOrder`. It does not call a venue client. `pnpm health` returned `{"status":"ok","liveTrading":"OFF","liveOrdersLocked":true}`. Cap numbers, lag `1000`, and funding interval `8` are fixtures and are NOT IN SOURCE. Decision 0072 records futures fills, funding, and fees and does not change these checks.

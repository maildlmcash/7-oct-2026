# 0054 — Futures baseline

Status: accepted for a futures label, horizon, cost-aware net, and model artifact kept separate from Spot. No order is placed.

## Context

TASK 12.B.01 asks for futures labels, a futures horizon, a cost model, and a model artifact that cannot be mixed with Spot. The net outcome must include funding and liquidation.

Design page 8 publishes the futures signed score as 100 times the weighted sum of PriceTrend, OIPriceImpulse, TakerFlow, FundingCrowding, BasisSignal, LiquidationFlow, and CrossVenueConfirmation, with weights 18, 18, 16, 14, 12, 12, and 10. Each component is on the closed interval from -1 to +1, and the total is clamped from -100 to +100. The same page says FundingCrowding must be validated with rolling historical conditional returns before it is treated as contrarian or momentum. The source does not say which. Design page 11 names Spot horizons 1m, 5m, 15m, and 1h and says the futures horizon and contract family stay separate. It does not name a futures duration. Design page 9 says funding alone is not the short or long rule. Decision 0052 records the linear and inverse payoff identities in currency units. Decision 0053 records derivatives inputs and leaves direction null. The source names no conversion from a funding rate or a funding interval into a return, and it names no Brier, log-loss, drawdown, or uncertainty arithmetic.

## Decision

`services/futures-baseline.mjs` stores the futures artifact under kind `futures`. Spot walk-forward evaluation rejects that store, and futures evaluation rejects a Spot baseline store. A futures manifest cannot be pinned by the Spot walker. A Spot manifest cannot be pinned as futures. Spot feature names are rejected by the futures scorer, and futures feature names are rejected by the Spot scorer. An inverse model does not satisfy a linear label.

The score uses the published weights. A missing component returns `signed feature is missing` and does not become zero. An explicit zero stays neutral. Each component is clipped to [-1, 1] before weighting, and the total is clamped to [-100, 100]. The caller supplies the sign of FundingCrowding. This module does not choose contrarian or momentum. `calibratedProbability` stays null. Logistic, gradient-boosted, isotonic, and Platt parameters are not fitted.

The horizon is a caller-supplied name plus a positive duration. Spot horizons are not imported. The duration is a fixture because design page 11 names none. The label is the contract-family mark return. Linear return uses the start mark as the denominator. Inverse return uses the outcome mark as the denominator. That reading divides the decision 0052 payoff by notional and omits a side, because the market label has no side. The source does not write that algebra. Contract PnL in currency units stays in `services/contract-specs.mjs`.

The walk-forward net is the label return plus the execution-cost net return plus the caller funding plus the caller liquidation. Funding and liquidation are signed decimals supplied by the caller. A missing funding key is `unsupported field`. A blank funding value is `funding is not configured`. Neither becomes zero. An uncertain execution cost leaves the net null, writes no outcome, and does not publish a partial sum. The stored label keeps `costsApplied` false. The checksum is SHA-256 of canonical JSON. Two evaluations of one pinned manifest match, including a copy made with `structuredClone`. Brier, log loss, drawdown, and uncertainty stay formula `NOT IN SOURCE` with null values. Calibration bins stay empty because calibrated probability is null.

The module does not place an order, does not change `services/baseline-model.mjs`, `services/walk-forward.mjs`, `services/contract-specs.mjs`, `services/derivatives-features.mjs`, or `services/market-features.mjs`, and does not add a PostgreSQL table. Decision 0055 records the futures risk diagnostic and does not change this score.

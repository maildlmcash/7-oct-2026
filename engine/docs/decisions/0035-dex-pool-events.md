# 0035 — One EVM and one Solana DEX pool event source

Status: accepted for Uniswap v3 and Raydium CPMM pool swap and liquidity events.

## Context

TASK 08.C.01 asks for pool swap and liquidity events from one EVM source and one Solana source, with token decimals, pool allowlists, finality, reorg handling, and source provenance. Unsupported pools and unverified events must be marked unavailable.

The design candidate table names Uniswap v2/v3/v4 on Ethereum as the first EVM row and Raydium as the first Solana row. Design page 5 says a DEX event keeps block number, block hash, transaction index, log index, and pool address, and that a reorg revises affected rows to the canonical chain. It also says to filter Solana log notifications by the named finalized or confirmed commitment. No Ethereum confirmation count is named. The Uniswap subgraph overview was read on 2026-10-06. It describes indexing, and its public explorer endpoints are not a live execution feed. This module does not query The Graph.

The Uniswap v3 pool event interface was read on 2026-10-06 from `IUniswapV3PoolEvents.sol`. Swap, Mint, and Burn are the swap and liquidity events. Swap amounts are signed. Mint and Burn token amounts are unsigned. Initialize, Collect, Flash, and the other pool events are not swap or liquidity events. Uniswap v2 and v4 were not given a second interface.

Raydium program addresses were read on 2026-10-06. The mainnet CPMM program id is `CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C`. The CPMM instruction reference names SwapBaseInput, SwapBaseOutput, Deposit, and Withdraw as the swap and liquidity instructions. Initialize creates a pool. Fee collection and admin instructions are not pool swap or liquidity events. The CLI example sets wrapped SOL mint `So11111111111111111111111111111111111111112` and `AMOUNT_RAW="10000000"` with the comment `0.01 SOL`. The same page says `1_000_000_000` raw units is 1 SOL. That is 9 decimals. The sample quote `10000000 -> 1640000` is an illustration, not an ingested amount. `logsSubscribe` on 2026-10-06 names commitments `processed`, `confirmed`, and `finalized`, and the default is `finalized`. Its example mentions the System Program, not a Raydium pool. No websocket is opened.

## Decision

`services/dex-pool-events.mjs` stores in-memory rows for Uniswap v3 on Ethereum and Raydium CPMM on Solana. The caller supplies the pool allowlist. An empty allowlist or any other pool is stored as unavailable with reason `unsupported pool`. Token decimals must equal that allowlist entry. Wrapped SOL must use 9 decimals. Amounts stay integer strings. A fractional amount is not stored. The raw example `10000000` stays `10000000`.

An EVM row keeps block number, block hash, transaction index, log index, and pool. Before a canonical head it is unavailable with reason `unverified`. `noteCanonicalChain` marks it available with finality `canonical` only when the block hash is in the head. A later head that drops the hash revises that row to unavailable with reason `reorg` and does not delete it. A Solana row keeps the CPMM program id, pool, signature, slot, and commitment. `confirmed` and `finalized` are available with that finality. `processed` stays unavailable with reason `unverified` even if the slot is later listed. A slot list that omits an admitted slot revises that row to `reorg`. The same EVM log identity, or the same Solana signature, marks the later row `duplicate` and does not replace the first. Unknown keys, including a last-trade price, are not copied. v2, v4, Flash, Initialize, and a different program id stay unavailable. The module does not place an order. Decision 0036 ranks whale eligibility separately and does not treat these pool events as a current list of 15 whales.

## Evidence

`pnpm test:dex-pool-events` passed 5/5. A Uniswap v3 Swap on the caller fixture pool is unverified until its block hash is in the canonical head, then finality is `canonical`. A later head with a different hash revises that same row to `reorg`. Mint with unsigned amounts becomes canonical. A negative Mint amount is unverified and is not stored. A decimal mismatch stays `token decimals` after the head. The amount `0.01` is not stored. The Raydium SwapBaseInput amount `10000000` stays that integer with wrapped SOL decimals 9, and the row does not contain `0.01` or `1640000`. `processed` stays unverified after its slot is listed. `confirmed` and `finalized` are available, and a slot list that omits the slot revises the confirmed row to `reorg`. Deposit is available. Initialize, a wrong program id, an empty allowlist, Uniswap v2, Uniswap v4, and Flash are unavailable. An extra price `0.001` is not copied. A duplicate does not replace the first row. `pnpm health` stayed `liveTrading` `OFF` and `liveOrdersLocked` true.

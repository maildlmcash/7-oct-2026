# 0077 — Combined Retailer and Customer profiles

Status: accepted for combined Retailer and Customer profiles. A second profile is allowed only for that pair. Catalog permissions stay empty. Combined identity is two profiles, not a new role.

## Context

TASK 17.A.02 asks for one identity to hold both Retailer and Customer profiles when policy permits, and for separate identities to keep working. Profile capability checks stay explicit. Tests must cover data isolation and role removal that does not leave orphaned ownership.

Design section 12 names the seats each role may create. It does not name a combined role. Design page 10 includes profile/security in customer navigation and says a Customer receives no commission control or downstream-user creation by default. Decision 0076 keeps one assignment per subject and rejects the role name `Retailer+Customer`. `authorizeShell` is unchanged. Commission basis and caps are not in this task.

## Decision

`services/role-profiles.mjs` exports `createProfileStore`, `assignProfile`, `recordProfileResource`, `readProfileResource`, `removeProfile`, and `PROFILE_LIMITATIONS`.

The profile store keeps the delegation fields `tenants`, `assignments`, and `capabilities`, plus `profiles` and `resources`. A store from `createDelegationStore` has no profile list, so profile calls return `unsupported field` and write nothing. `delegateRole` is still the first-seat writer. One subject still has one assignment. A second profile is recorded only when that call returns `role is already recorded` and the two roles are exactly Retailer and Customer in the same tenant. Any other second role returns `profile is not combined`. The same profile again returns `profile is already recorded`. An exact replay returns `idempotentReplay` true.

A resource is owned by the subject and the named profile. A read or write that does not name a profile the caller holds returns `profile is not held`. A held profile cannot read another profile's resource or another subject's resource. The reason is `resource owner is outside scope`. Holding both profiles does not let the Customer profile read the Retailer resource.

Removal uses the same descendant, capability, and subtree rules as seat creation. A profile that still owns a resource, with no successor, returns `ownership would be orphaned` and the store stays unchanged. A successor must already hold that same profile in the same tenant. Ownership then moves to the successor and the removed profile is gone. A successor with the other profile returns `profile is not held`. A successor in another tenant returns `tenant is outside subtree`. The subject cannot succeed itself. Removing a profile that owns nothing leaves the other profile and its resources. If the removed profile was the assignment role and another profile remains, the assignment is retargeted to the remaining profile. If no profile remains, the assignment is removed.

A Retailer actor still cannot create or remove a Customer. The reason is `capability grantor is not configured`. A Customer actor still cannot create a downstream seat. A supplied permission is `permission is not granted` and is not stored. A credential or bearer value is not stored. `liveTrading` stays `OFF` and `liveOrdersLocked` stays true. No PostgreSQL table was added. `packages/contracts/src/roles.mjs`, `services/role-delegation.mjs`, and `services/shell-capabilities.mjs` were not changed.

## Evidence

`pnpm test:role-profiles` passed 3/3, duration_ms 235.285359. `fixture-only-retailer` holds Retailer only and `fixture-only-customer` holds Customer only. A repeated Retailer profile is `profile is already recorded`. Admin and Distributor as a second role are `profile is not combined`. Admin cannot assign Customer. `Retailer+Customer` is `role scope denied` and is not stored. Each separate identity's read of the other profile is `profile is not held`. `fixture-both` receives Retailer and then Customer. The assignment stays Retailer and the profile list holds both. `fixture-both-reverse` receives Customer and then Retailer. The assignment stays Customer. A Retailer profile in `tenant-b` cannot be added to the Customer in `tenant-a-child`. The Customer profile cannot read `fixture-both-retailer`. The Retailer profile cannot read `fixture-both-customer`. `fixture-retailer-2` and `fixture-customer-2` cannot read either resource. The combined subject presented as Retailer cannot create a Customer. The same subject presented as Customer cannot create a Retailer. Permission `checklist.write` is `permission is not granted` and is not stored.

Removing Retailer from `fixture-both` while `fixture-owned-retailer` has no successor returns `ownership would be orphaned`. The owner stays `fixture-both`. A Customer successor is `profile is not held`. `fixture-retailer-b` is `tenant is outside subtree`. The subject as its own successor is `resource owner is outside scope`. Successor `fixture-retailer-2` receives `fixture-owned-retailer`. The removed Retailer profile cannot read it. The Customer resource stays with `fixture-both`, and `fixture-customer-2` still cannot read it. The assignment is retargeted to Customer. Removing the empty Retailer profile from `fixture-both-reverse` leaves the Customer resource and the Customer assignment. Removing that Customer profile without a successor is `ownership would be orphaned`. Successor `fixture-customer-2` receives it, the assignment is removed, and `fixture-kept-retailer` stays with `fixture-retailer-2`. A Retailer actor cannot remove a Customer. `bearer fixture-token` is not stored. A commission field is `unsupported field` and is not stored. `pnpm test:roles` passed 2/2, duration_ms 261.844069, and the six catalog lists stayed empty. `pnpm test:role-delegation` passed 3/3, duration_ms 154.968644. Those re-checks do not replace the durations recorded for decisions 0011 and 0076. `pnpm health` returned `{"status":"ok","liveTrading":"OFF","liveOrdersLocked":true}`. Super Distributor descendants, the Retailer seat-creation grantor, and commission basis and caps are NOT IN SOURCE. Decision 0078 records commission basis and caps and does not change these profiles.
